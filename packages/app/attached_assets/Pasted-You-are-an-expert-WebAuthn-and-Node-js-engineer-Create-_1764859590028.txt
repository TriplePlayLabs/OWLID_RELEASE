Back-end requirements (index.js):
1. Basic Express setup
   - Use express.json() for JSON bodies.
   - Serve static files from ./public.
   - Detect rpID and expectedOrigin from incoming requests:
     - On each request, derive host = req.headers.host.split(":")[0].
     - rpID = host
     - expectedOrigin = "https://" + host

2. In-memory data structures
   - Maintain:
     - users: Map<string, { id: string, username: string, credentials: WebAuthnCredential[] }>
       - id: a stable user id (for example random base64url or UUID).
       - username: string.
       - credentials: array of:
         - credentialID (Buffer or base64url string)
         - publicKey
         - counter
         - transports (optional)
   - You can store credentialID as base64url string internally to simplify JSON, but convert back to Buffer where needed.

3. WebAuthn registration (create credential)
   - Endpoint: POST /webauthn/register/options
     - Request body: { username: string }
     - Behavior:
       - Look up or create a user for this username.
       - Use @simplewebauthn/server to generateRegistrationOptions:
         - rpName: "Replit WebAuthn POC"
         - rpID: derived as above
         - userID: user.id as Buffer or string
         - userName: user.username
         - authenticatorSelection: userVerification: "preferred"
         - attestationType: "none"
       - Store the generated options (challenge + username) in a simple in-memory "pendingChallenges" map so you can verify later.
       - Return the options to the client as JSON.
   - Endpoint: POST /webauthn/register/verify
     - Request body: { username: string, attestationResponse: any }
     - Behavior:
       - Look up the user and the matching pending registration challenge.
       - Call verifyRegistrationResponse from @simplewebauthn/server with:
         - response: attestationResponse
         - expectedChallenge: challenge from stored options
         - expectedOrigin: derived as above
         - expectedRPID: rpID
       - If verification succeeds:
         - Extract credential ID, public key, counter, etc.
         - Add a new credential entry to user.credentials.
       - Return { verified: true, userId: user.id } on success, or { verified: false } on failure.

4. WebAuthn authentication (login)
   - Endpoint: POST /webauthn/authenticate/options
     - Request body: { username: string }
     - Behavior:
       - Look up user by username.
       - If user or credentials do not exist, return an error.
       - Use generateAuthenticationOptions from @simplewebauthn/server:
         - allowCredentials: the list of credential IDs for this user.
         - userVerification: "preferred".
       - Store challenge + username in a "pendingAuthChallenges" map.
       - Return options to the client.
   - Endpoint: POST /webauthn/authenticate/verify
     - Request body: { username: string, assertionResponse: any }
     - Behavior:
       - Look up user and pending auth challenge.
       - Find the relevant credential by credentialID from assertionResponse.
       - Call verifyAuthenticationResponse with:
         - response: assertionResponse
         - expectedChallenge
         - expectedOrigin
         - expectedRPID: rpID
         - authenticator: current credential info for this user
       - If verified:
         - Update the stored counter for that credential from verification result.
         - Return { verified: true, userId: user.id, username: user.username }.

5. "Prove identity by signing a message" endpoint
   - Purpose: bind an arbitrary message (for example a Merkle root or "I am user X at time T") to the WebAuthn assertion.
   - Approach:
     - We will encode the message into the WebAuthn challenge, so the signature proves that this specific user approved this message.
   - Endpoint: POST /webauthn/prove/options
     - Request body: { username: string, message: string }
     - Behavior:
       - Look up user and credentials as in authentication.
       - Compute a challenge that depends on the message, for example:
         - challenge = random 32 bytes, or
         - hash = SHA-256(message + random nonce)
         - For simplicity, you can just use generateAuthenticationOptions and store { challenge, username, message } together in memory.
       - Use generateAuthenticationOptions with:
         - allowCredentials: user credentials
         - challenge: override with your own random bytes (the link to the message is logical: you will store message next to the challenge in memory).
       - Store { username, message, challenge } in a "pendingProofChallenges" map.
       - Return options to the client.
   - Endpoint: POST /webauthn/prove/verify
     - Request body: { username: string, message: string, assertionResponse: any }
     - Behavior:
       - Look up user and the stored entry in pendingProofChallenges for that username and message.
       - Verify assertion with verifyAuthenticationResponse:
         - expectedChallenge = stored challenge
         - expectedOrigin, expectedRPID as before.
       - If verified:
         - Return JSON with:
           - verified: true
           - userId
           - username
           - message
           - comment: "This user has cryptographically approved this message via WebAuthn"
       - This demonstrates how the same flow could be used to prove that a user approved a Merkle root or other identity data off-chain.

6. Helper utilities
   - Implement small helper functions to:
     - Convert between base64url and Buffer.
